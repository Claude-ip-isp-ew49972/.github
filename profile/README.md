<p>注册 Claude 之前要定的事，说到底是四个：用哪种出口、一个号占几条线、注册那一刻要核哪些字段、花到哪一步就该停。这四件事如果在下单前定不下来，后面每出一次问题就得重新决策一次，钱和时间都耗在反复上。这篇把四项做成可以打勾的清单，每项给出判定依据和「不选它的理由」，最后附上验收与退出条件，方便直接对着采购单核。</p>
<h2>一、先明确这份清单要回答的四个问题</h2>
<p>清单的价值不在于列全，而在于让每个选项都有明确的否决理由。四项决策各自独立，但顺序有讲究：先定类型，再定数量，然后定核对项，最后定预算和退出线。</p>
<h3>顺序为什么不能乱</h3>
<p>类型决定单价，数量决定总价，核对项决定这批货能不能用，退出条件决定用错了怎么止损。反过来做——先谈总价再定类型——通常会买到看着便宜、实际不可用的段。</p>
<h3>每一步的产出物</h3>
<p>第一项产出一句结论（例如「原生家宽、双 ISP 主备」），第二项产出一个数字（几条出口），第三项产出一张字段核对表，第四项产出一个止损线。四样凑齐，采购单就能直接下。</p>
<h2>二、第一项：出口类型与双 ISP 怎么选</h2>
<p>市面上号称住宅出口的产品大致三类：机房段伪装、普通住宅共享、原生家宽独享。前两类便宜，第三类贵，判断依据只看 ASN。</p>
<h3>三类出口的实际差别</h3>
<p>机房段的 org 会写着云厂商名字，一查就露；普通住宅共享是一个出口挂很多用户，复用率高、行为混杂；原生家宽独享是一条线归一个用户，ASN 与 org 都是本地运营商。注册场景建议至少到第二类，长期使用建议第三类。</p>
<h3>双 ISP 到底解决什么</h3>
<p>两条运营商链路互为备份，主链路抖动时自动切到备用，会话不中断；同时两条链路的归属都是住宅运营商，切换前后出口类型不变。它解决的是「连续性」和「归属一致性」两个问题，不是「让平台看不出」。同一批号落在同一个 /24 段、同一时间集中登录、绑定同一张卡，这些才是被算成一源的主要原因，双 ISP 不改变这些，得靠清单里的第二、三项去管。</p>

<h2>三、第二项：单号独享，还是同段共用</h2>
<p>这一项决定数量，也决定风险怎么分布。很多人把「同批号走同一段」当成省钱技巧，其实它是一种管理选择，代价写在后面。</p>
<h3>两种做法的分界</h3>
<p>主力号、绑了支付方式的号、要长期养着的号，走单号独享；临时号、只做查询的号、生命周期短的号，可以同段共用。判断标准是「这个号停了会不会影响收入」，会，就独享。</p>
<h3>同段共用要加的三道约束</h3>
<p>一是注册间隔不少于二十分钟；二是一张支付方式最多挂两到三个号；三是每号一套浏览器配置目录，Cookie 与本地存储不共享。三条都做到，同段共用的实际风险接近独享；少做一条，就等于把它们绑成一组。</p>
<h3>怎么数出需要几条</h3>
<p>数同时在线的号，不数总号数。二十个号里日常在线的常见是六到八个，加两成冗余，八到十条出口就够覆盖，其余走流量池。这样比按总号数下单省下近一半。</p>
<h2>四、第三项：注册链路上要逐项核对的字段</h2>
<p>下单前和开号前各核一遍，两次核对的项不一样。下单前核的是「这条线是什么」，开号前核的是「这台机器现在是不是真的走这条线」。</p>
<h3>下单前核三项</h3>
<p>ASN 与 org 是否为本地运营商、出口城市是否在你要的范围内、是否标了 proxy 或 hosting 标记。用 ipinfo.io 和 ip-api.com 各查一次，两个来源结果一致再付款，别只看商家页面截图。</p>
<h3>开号前核四项</h3>
<p>实际出口 IP 与订单一致、时区与出口城市一致、界面语言与该国主流语言一致、DNS 解析走的是同一条链路。第四项常被漏掉，用浏览器访问一个显示 DNS 出口的检测页即可，若解析出口与代理出口不同城，页面里会出现明显的不一致。</p>

<h2>五、第四项：预算上限、退出条件与复盘节点</h2>
<p>前三项定的是买什么，这一项定的是买到哪停、什么时候退。没有这一项，试错就会变成持续投入。</p>
<h3>预算怎么设上限</h3>
<p>按单号月成本倒推：独享家宽常见每月几十到两百元，双 ISP 更高一些，仅供参考。先算出「单号月成本 × 主力号数」作为基线，再留两成作为换线备用金。总额超过基线一倍还没跑通，就该停下来重新看类型选错了没有。</p>
<h3>三条退出条件</h3>
<p>连续两周验证次数超过三次、同一批号里两例以上同类型报错、商家无法提供 ASN 与城市的一致性证明。三条中任一成立，就走退出流程，别抱着「再等等看」。</p>
<h3>复盘节点定在哪</h3>
<p>开号后第七天、第三十天各复盘一次。第七天看环境是否一致、有没有异常验证；第三十天看用量与成本是否落在预算内。两次复盘都过，才把这一批列入常规运维，不再逐日盯。</p>
<h2>常见问答</h2>
<h3>双 ISP 出口是不是比单 ISP 更不容易被识别？</h3>
<p>答：这个说法把因果弄反了。双 ISP 的作用是链路冗余和归属一致，切换时出口类型不变、会话不断。它不改变账号的行为特征，也不解决同段集中登录的问题。指望靠它「不被识别」，方向从一开始就错了。</p>
<h3>清单里的字段要每次开号都核吗？</h3>
<p>答：不用每次都全核，但每周至少全核一次。日常开号只核两项：实际出口 IP 是否与记录一致、时区语言是否被动过。这两项出错概率最高，也最容易导致当天白干。</p>
<h3>预算有限，四项里哪项可以先降配？</h3>
<p>答：降第二项，不降第一、三项。出口类型降到住宅共享还能用，字段核对一旦省掉，买回来的东西是不是你要的都不知道。第一项降级等于换了个赛道，第三项省掉等于闭眼下单，这两个都不划算。</p>
<h3>怎么验证商家说的「原生家宽」是真的？</h3>
<p>答：三条一起看。ASN 查归属、rDNS 看解析记录是否指向运营商、连续七天同一 IP 是否稳定。三条都对得上，基本可以信；只有页面标注对得上，就当广告看。要求商家提供近期同段的查询截图，也是合理的做法。</p>
